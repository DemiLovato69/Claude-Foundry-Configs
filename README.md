# Claude Code configuration

Personal Claude Code user configuration for the Palantir Foundry Anthropic
proxy. The repository is designed to be cloned directly to `~/.claude` on a
fresh machine.

## Included

- `settings.json`: model aliases, permissions, and UI defaults.
- `agents/`: custom `rubberducky` and `stackoverflow` subagents.
- `skills/`: self-contained Ponytail, Rubber Ducky, and Stack Overflow skills.

Claude-generated history, project transcripts, caches, sessions, and plugin
marketplace data are ignored. Credentials are not stored in this repository.

## Prerequisites

- [Git](https://git-scm.com/)
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code/overview)
- Access to a Palantir Foundry Anthropic proxy
- An API key exposed as `CLAUDE_API_KEY`
- The proxy endpoint exposed as `ANTHROPIC_BASE_URL`

Confirm that Claude Code and both environment variables are available:

```sh
claude --version
test -n "$CLAUDE_API_KEY" && echo "CLAUDE_API_KEY is set"
test -n "$ANTHROPIC_BASE_URL" && echo "ANTHROPIC_BASE_URL is set"
```

Add the key and endpoint to your shell environment if needed. For example, with
Zsh:

```sh
export CLAUDE_API_KEY="your-key"
export ANTHROPIC_BASE_URL="https://your-foundry-host/api/v2/llm/proxy/anthropic"
```

Put these exports in a secure shell configuration or secret manager if they must
persist. Never add the key or endpoint to this repository.

## Fresh installation

If Claude Code has not created `~/.claude` yet, clone the repository directly:

```sh
git clone <REPO_URL> "$HOME/.claude"
```

Then start Claude Code:

```sh
claude
```

Claude will create its ignored runtime directories alongside the tracked
configuration.

## Replacing an existing setup

Exit Claude Code before replacing an existing configuration. Back it up, then
clone this repository:

```sh
mv "$HOME/.claude" "$HOME/.claude.backup.$(date +%Y%m%d-%H%M%S)"
git clone <REPO_URL> "$HOME/.claude"
```

Review the backup before deleting it. Copy individual local settings back only
if they do not conflict with this repository.

## Configuration

`settings.json` currently:

- Uses `CLAUDE_API_KEY` through `apiKeyHelper`.
- Sends Anthropic requests to the proxy specified by `ANTHROPIC_BASE_URL`.
- Selects the configured Opus, Sonnet, and Haiku model identifiers.
- Uses Opus by default with extended thinking enabled.
- Uses the dark theme.
- Disables Claude Code's automatic updater, so updates must be installed manually.
- Sets the default permission mode to `acceptEdits`.

The endpoint and model identifiers are organization-specific. Update
`ANTHROPIC_BASE_URL` if the Foundry environment changes, or edit `settings.json`
if the model identifiers change.

`acceptEdits` allows Claude to apply file edits without asking for approval each
time. Change `permissions.defaultMode` if a more restrictive default is desired.

## Plugins

Plugin marketplace checkouts are generated by Claude Code and are intentionally
not tracked. Install plugins from inside Claude Code instead:

```text
/plugin install <plugin-name>@claude-plugins-official
```

Review a plugin and its external dependencies before installing it.

## Updating

Check for local changes, then fast-forward to the latest configuration:

```sh
git -C "$HOME/.claude" status --short
git -C "$HOME/.claude" pull --ff-only
```

Claude's ignored runtime files do not affect updates. Commit, discard, or move
intentional changes to tracked files before pulling.

Because the automatic updater is disabled in `settings.json`, update the Claude
Code application separately using the same method used to install it.

## Troubleshooting

### API key is missing

Verify that Claude's shell can read the variable:

```sh
printenv CLAUDE_API_KEY
```

An empty result means the variable is not exported in that shell.

### Gateway or model errors

Confirm that `ANTHROPIC_BASE_URL` points to an accessible Foundry endpoint and
that the model identifiers in `settings.json` are available to the account. This
configuration is not set up for the public Anthropic API without modification.

### Agents cannot load skills

Each skill must contain a `SKILL.md` directly below its directory:

```sh
ls "$HOME/.claude/skills"/*/SKILL.md
```

The skill directories are regular tracked files and do not depend on symlinks or
another dotfiles repository.

## Security

Do not commit API keys, environment files, prompt history, project transcripts,
session data, or generated plugin state. Before pushing changes, inspect:

```sh
git -C "$HOME/.claude" status --short
git -C "$HOME/.claude" diff --cached
```
